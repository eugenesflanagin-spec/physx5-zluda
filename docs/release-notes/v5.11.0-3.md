# physx5-zluda 5.11.0-3

## What it is

An Arch Linux package of the open-source **NVIDIA PhysX SDK 5.11** built *with its GPU
(CUDA) simulation kernels*, set up so those kernels run on an **AMD Radeon GPU through
ZLUDA**. Everything installs into `/opt/physx5`: the PhysX libraries and headers (for your
own programs), about 70 PhysX sample "snippets", a headless self-test, and a launcher
(`physx5-zluda-run`) that sets the environment.

It is for developers and tinkerers with an AMD GPU who want to try PhysX 5 GPU rigid
bodies, articulations and deformables on Linux. It does **not** make games use GPU PhysX.

This is the first release on GitHub. The AUR had 5.11.0-1.

## What changed since 5.11.0-1

Same PhysX commit (`6dc53585`), same CUDA 13.4 pieces, same GPU code. The changes are in the
packaging, the launcher and the documentation:

- **Licences fixed.** The package licence is now Apache-2.0 (the licence of the PhysX SDK
  sources that are built), and it ships NVIDIA's real CUDA EULA for the bundled
  `libcudart.so.13` (5.11.0-1 accidentally installed the CCCL licence under that name).
  This project's own files (shim, self-test, launcher, menu entries, docs) are now
  explicitly MIT, and `CREDITS.md` lists every source with its licence.
- **CMake fix:** `find_package(PhysX)` with `CMAKE_PREFIX_PATH=/opt/physx5` now works. In
  5.11.0-1 the installed CMake files demanded a CUDA toolkit and pointed at a file inside the
  build folder, so CMake projects could not use the package.
- **Launcher fixes:** `physx5-zluda-run --help` prints the real help, `--list` includes
  `gputest`, and `--cpu-only gputest` now really runs the self-test on the CPU.
- **Menu entries** use generic AMD GPU wording instead of naming one card.
- **Build:** the missing `rapidjson` build dependency was added (found by building in a
  clean Arch container). The patch has clean headers and a modification notice.
- **Docs:** new plain-words [User Guide](https://github.com/eugenesflanagin-spec/physx5-zluda/blob/master/docs/USER-GUIDE.md)
  (install, every option, troubleshooting, glossary); README gains Install,
  Troubleshooting and Credits sections; developer notes in `docs/DEVELOPER-NOTES.md`.

## Install

```sh
yay -S zluda-preview-bin                          # ZLUDA first (provides libcuda.so.1)
sha256sum -c SHA256SUMS --ignore-missing          # check the download
sudo pacman -U physx5-zluda-5.11.0-3-x86_64.pkg.tar.zst
physx5-zluda-run gputest                          # exit 0 and "RESULT: GPU PhysX ENGAGED" = working
physx5-zluda-run --list                           # sample programs
```

Or build it yourself: `yay -S physx5-zluda` (AUR). The first GPU start is slow while ZLUDA
compiles and caches the kernels in `~/.cache/zluda`.

Updating from 5.11.0-1: just install this package over it (`pacman -U` or `yay -Syu`).

## Requirements

- An AMD GPU supported by ZLUDA and ROCm (verified on Radeon RX 9070 XT / RDNA 4 with ROCm 10
  and `zluda-preview-bin` 7.preview.13; newer ZLUDA builds are not re-verified, so run
  `gputest` after a ZLUDA update)
- freeglut / GLU / X11 libraries for the windowed snippets (pulled in automatically)
- Do not install NVIDIA's `nvidia-utils` / `cuda` packages alongside it: they replace ZLUDA's
  `libcuda.so.1`

## Known limits

- 12 of PhysX's 488 GPU kernels use indirect function calls that ZLUDA cannot compile:
  **particle systems (PBF) and the new ConvexCore geometry (cylinders/cones) do not work on
  the GPU**. Rigid bodies, joints, articulations, deformable volumes/surfaces and SDF meshes do.
- A small LD_PRELOAD shim (source included) works around three ZLUDA gaps; the launcher
  loads it for you.
- ZLUDA is pre-release software. Not affiliated with NVIDIA, AMD or the ZLUDA project.
